# Этап 6: обновление, миграция и контроль Windows-диска

Дата: 2026-09-22. Статус: исходники и автоматические проверки выполнены;
закрепление release pins, сборка image/bundle и установленная приёмка продолжаются.
Этот документ пока не означает допуска следующей продуктовой задачи.

## Что реализовано

- `Update` проверяет принятый bundle и готовит отдельные source/profile, host config,
  Windows helpers, config/workflow/manifest и state. Descriptor переключается последним.
- Миграция четырёх ролей на семь сохраняет исходный snapshot и повторно проверяет
  его replay; новая оболочка schema 2 сохраняет прошлый цикл, бюджеты и результаты.
  Старое подтверждение dev аннулируется. Исторический финальный статус остаётся
  `legacy_not_recorded`: ретроспективных GitHub mutations нет.
- Приватная резервная копия содержит исходные state/config/workflow/manifest;
  App/Codex auth, SSH identity и workspace worker сохраняются.
- Pending journal блокирует Start. Повтор продолжает тот же переход. Завершённые
  проверки не запускаются повторно после прерывания переключения descriptor.
- `Rollback-Update` проверяет неизменность обоих состояний и выбирает старый комплект.
  После первого запуска нового runtime или новых записей такой откат запрещён.
- Windows manager определяет физические тома зарегистрированных VHDX и передаёт
  свежие показания по существующему каналу. Проверяются установка, обе среды,
  поколение процесса, boot и возраст до 15 секунд, включая sleep.
- Общий том учитывается один раз; эффективный остаток — минимум Windows/WSL.
  Пороги: менее 10 GiB предупреждение; менее 5 GiB или unknown закрывает допуск
  и вызывает штатную остановку активного worker с сохранением работы.
- Панель раздельно показывает Windows и WSL, время измерения, состояние и причину.
  Дополнительный доступ worker к Windows не добавлен.

Тесты update используют настоящие приватные файлы/flock и Windows journals;
внешние WSL/service операции в Windows fixture заменены управляемыми ответами.
Это не заменяет приёмку устанавливаемого release image и реального нового manager.
Историческая issue #132 не запускалась и не изменялась; для replay использована копия.

Первый release candidate (`76c5884`, профиль `cfc6c34`) прошёл strict profile и
container acceptance, но чистая установка обнаружила добавление трёх байт BOM
в PowerShell 5.1. Контроль размера остановил установку до использования архива.
Исправление задаёт UTF-8 без BOM для stdin создаваемого процесса и восстанавливает
кодировку консоли; добавлен тест с принудительным BOM и настоящей WSL.
Этот candidate не считается принятым; итоговые pins будут пересобраны.

Второй candidate (`faf45d6`, профиль `58372f8`) прошёл чистую установку с
`SkipLogin`: isolation smoke, read-only GitHub inspection, readiness и confirmed
Stop. На отдельной копии старой установки обнаружен ещё один реальный дефект:
сохранённый cgroup содержит динамический префикс WSL и после рестарта отличается.
Guardian теперь проверяет оба payload на отсутствие процессов и принадлежность
одному service; неизвестные и занятые группы не принимаются. Новый operator
подтверждает уже завершённый worker свежим scope-bound proof без повторного
старого Stop. Проверено 86 runtime и 34 operator тестами; нужна повторная приёмка.

Третий candidate выявил неполное описание совместимости: реальный профиль этапа 5
также меняет read timeout 5000 → 60000 и добавляет точную container sandbox policy.
Миграция теперь допускает только этот известный переход; расширение writable roots,
включение сети и произвольные настройки Codex отвергаются. Новый полный gate:
623 Elixir-теста, 0 ошибок, 6 opt-in skips, coverage 100%, Dialyzer без ошибок.

На чистой установке второго candidate проверена настоящая цепочка manager →
controller → защищённая панель: один общий Windows-том и отдельные WSL-показатели.
Принудительное завершение только тестового manager закрыло панель и записало
свежее `last_shutdown` с `stopped: true`; фильтр задач оставался пустым.

## Незавершённая релизная приёмка

1. Закрепить Symphony и профиль, получить strict pin/profile contract и hosted CI.
2. Собрать image штатным builder из чистого commit; повторить container acceptance.
3. Собрать проверенный bundle, проверить чистую установку и обновление прежней версии.
4. Подтвердить цепочку Windows manager → controller → dashboard на установленной версии,
   Stop/export, сохранение auth/model/workspace и поведение при потере manager/свежести.
5. Зафиксировать точные SHA/image ID/hash комплекта и оставшиеся ограничения.

Существующие advisories зависимостей были показаны Hex при `make all`; этот этап
их не исправляет. Шесть live E2E требуют своих внешних fixtures и не заявлены как PASS.
Миграция ограничена переходом с четырёх на семь ролей, не является универсальным
обновлением произвольных контрактов. Изменение профиля после начала работы требует
отдельного совместимого перехода; слепой restore состояния не предусмотрен.
